# Quickstart: Aspire-to-Bicep PoC

**Branch**: `004-aspire-to-bicep` | **Date**: 2026-02-23

Convert a .NET Aspire starter application into a Radius-deployable `app.bicep` using the `rad bicep generate --from-aspire` command.

## Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| .NET SDK | 8.0+ | Create and build Aspire applications |
| Azure Developer CLI (`azd`) | Latest | Generate infrastructure Bicep from Aspire |
| Radius CLI (`rad`) | Built from `004-aspire-to-bicep` branch | Run the conversion command |
| Docker Desktop | Latest | Local Kubernetes cluster for Radius |
| Go | 1.26.0+ | Build the Radius CLI from source |

## Step 1: Create an Aspire Starter Application

```bash
mkdir aspire-demo && cd aspire-demo
dotnet new aspire-starter -n AspireDemo
```

This generates a solution with:
- `AspireDemo.Web` — frontend Blazor service
- `AspireDemo.ApiService` — backend API service
- `AspireDemo.AppHost` — Aspire orchestrator (references Redis)

## Step 2: Generate azd Infrastructure Artifacts

```bash
cd AspireDemo.AppHost
azd init
azd infra synth
```

This produces a `./infra` directory with Bicep files:

```
infra/
├── main.bicep
├── main.parameters.json
├── apiservice/
│   └── apiservice.bicep          # Microsoft.App/containerApps for API
├── webfrontend/
│   └── webfrontend.bicep         # Microsoft.App/containerApps for frontend
└── cache/
    └── cache.bicep               # Redis dependency
```

These are Azure Container Apps Bicep definitions. The conversion reads these to produce Radius equivalents.

## Step 3: Build the Radius CLI (from source)

```bash
# Clone and checkout the feature branch
cd ~/projects/radius
git checkout 004-aspire-to-bicep

# Build the CLI
make build
```

The built binary is at `./dist/rad` (or `./dist/rad.exe` on Windows).

## Step 4: Convert Aspire Artifacts to Radius Bicep

```bash
cd ~/aspire-demo/AspireDemo.AppHost

rad bicep generate --from-aspire ./infra
```

**Expected console output:**

```
Converting Aspire artifacts from: ./infra
  Found 2 services: apiservice, webfrontend
  Found 1 dependency: cache (Redis)

Generating app.bicep...
  ✓ Application: aspire-demo
  ✓ Container: apiservice (image param: apiserviceImage)
  ✓ Container: webfrontend (image param: webfrontendImage)
  ✓ Dependency: cache (Applications.Datastores/redisCaches, Recipe-backed)
  ✓ Connection: webfrontend → apiservice
  ✓ Connection: apiservice → cache

Output written to: ./app.bicep
Mapping report written to: ./mapping-report.md

Gaps found: 0
Assumptions made: 3 (see mapping report for details)
```

**Generated files:**
- `app.bicep` — Radius application definition
- `mapping-report.md` — Field-level mapping from Aspire artifacts to Radius resources

## Step 5: Review the Generated app.bicep

The generated `app.bicep` will look like:

```bicep
// Generated by: rad bicep generate --from-aspire
// Source: ./infra
// Date: 2026-02-23T12:00:00Z

extension radius

@description('The ID of your Radius Environment. Set automatically by the rad CLI.')
param environment string

@description('The name of the Radius Application.')
param applicationName string = 'aspire-demo'

@description('Container image for apiservice.')
param apiserviceImage string = 'apiservice:latest'

@description('Container image for webfrontend.')
param webfrontendImage string = 'webfrontend:latest'

resource app 'Radius.Core/applications@2025-08-01-preview' = {
  name: applicationName
  properties: {
    environment: environment
  }
}

resource apiservice 'Radius.Compute/containers@2025-08-01-preview' = {
  name: 'apiservice'
  properties: {
    application: app.id
    environment: environment
    container: {
      image: apiserviceImage
      ports: {
        http: {
          containerPort: 8080
          protocol: 'TCP'
        }
      }
    }
    connections: {
      cache: {
        source: cache.id
      }
    }
  }
}

resource webfrontend 'Radius.Compute/containers@2025-08-01-preview' = {
  name: 'webfrontend'
  properties: {
    application: app.id
    environment: environment
    container: {
      image: webfrontendImage
      ports: {
        http: {
          containerPort: 8080
          protocol: 'TCP'
        }
      }
    }
    connections: {
      apiservice: {
        source: apiservice.id
      }
    }
  }
}

resource cache 'Applications.Datastores/redisCaches@2023-10-01-preview' = {
  name: 'cache'
  properties: {
    application: app.id
    environment: environment
  }
}
```

Key points:
- Image references are Bicep parameters — override at deploy time
- Redis uses a Recipe-backed Portable Resource (no manual infra provisioning)
- Connections express the `webfrontend → apiservice → cache` topology

## Step 6: Review the Mapping Report

Open `mapping-report.md` to see the full field-level lineage:

```markdown
## Field-Level Mapping

### apiservice (Radius.Compute/containers)

| Target Field                         | Value            | Source File                    | Source Field                             | Status |
|--------------------------------------|------------------|--------------------------------|------------------------------------------|--------|
| name                                 | apiservice       | apiservice/apiservice.bicep    | resource.name                            | Mapped |
| container.image                      | apiserviceImage  | apiservice/apiservice.bicep    | template.containers[0].image             | Mapped |
| container.ports.http.containerPort   | 8080             | apiservice/apiservice.bicep    | configuration.ingress.targetPort         | Mapped |
```

Every field in `app.bicep` traces back to a specific source file and field. Gaps and assumptions are called out explicitly.

## Step 7: Deploy with Radius

```bash
# Ensure a local Radius environment is running
rad init

# Build container images (if not already available)
docker build -t apiservice:latest ./AspireDemo.ApiService
docker build -t webfrontend:latest ./AspireDemo.Web

# Deploy the converted application
rad deploy app.bicep
```

Override images if using a registry:

```bash
rad deploy app.bicep \
  --parameters apiserviceImage=myregistry.azurecr.io/apiservice:v1 \
  --parameters webfrontendImage=myregistry.azurecr.io/webfrontend:v1
```

## Step 8: Verify the Deployment

```bash
# Check the application
rad app show aspire-demo

# List resources in the application
rad resource list --application aspire-demo

# Access the frontend (get the endpoint URL)
rad resource show containers webfrontend --application aspire-demo
```

The application graph should show:
- `aspire-demo` (Application)
  - `webfrontend` (Container) → connects to `apiservice`
  - `apiservice` (Container) → connects to `cache`
  - `cache` (Redis, Recipe-backed)

## Step 9: Verify Idempotency (FR-012)

Re-run the conversion and confirm byte-for-byte identical output:

```bash
# Re-run with deterministic flag (fixed timestamps)
rad bicep generate --from-aspire ./infra --deterministic
cp app.bicep app-run1.bicep
cp mapping-report.md mapping-report-run1.md

# Run again
rad bicep generate --from-aspire ./infra --deterministic

# Compare — should produce no differences
diff app-run1.bicep app.bicep
diff mapping-report-run1.md mapping-report.md
```

Both `diff` commands should produce no output, confirming the conversion is deterministic.

## Common Options

```bash
# Specify custom output paths
rad bicep generate --from-aspire ./infra \
  --output ./deploy/app.bicep \
  --report ./deploy/mapping-report.md

# Override the application name
rad bicep generate --from-aspire ./infra --app-name my-custom-app

# Suppress console report (file still generated)
rad bicep generate --from-aspire ./infra --quiet
```

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `Error: Input directory does not contain any Bicep files` | Wrong path or `azd infra synth` not run | Run `azd infra synth` first, point `--from-aspire` at the `infra/` directory |
| `Error: Multiple Aspire projects detected` | Directory contains multiple `main.bicep` files | Point to a single Aspire project's infra directory |
| Placeholder ports in output | Source Bicep missing `ingress.targetPort` | Edit `app.bicep` to set actual port — see mapping report for details |
| `rad deploy` fails on image pull | Container images not built or not accessible | Build images locally or push to a registry and use `--parameters` to override |
| Redis connection fails at runtime | No default Redis Recipe configured | Run `rad env update` to configure a Redis Recipe for your environment |
