# CLI Contract: `rad bicep generate --from-aspire`

**Branch**: `004-aspire-to-bicep` | **Date**: 2026-02-23

## Command Syntax

```
rad bicep generate --from-aspire <path> [flags]
```

## Description

Generate a Radius-deployable app.bicep file from Aspire-generated infrastructure artifacts (azd infra synth output).

This command reads Bicep files generated by `azd infra synth` for a .NET Aspire application and produces a Radius-compatible app.bicep file along with a mapping report documenting the conversion.

## Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| (none) | — | No positional arguments |

## Flags

| Flag | Short | Type | Default | Required | Description |
|------|-------|------|---------|----------|-------------|
| `--from-aspire` | — | `string` | — | Yes | Path to the directory containing `azd infra synth` output Bicep files |
| `--output` | `-o` | `string` | `./app.bicep` | No | Path for the generated app.bicep output file |
| `--app-name` | — | `string` | (derived from Aspire project) | No | Name for the Radius application resource |
| `--report` | — | `string` | `./mapping-report.md` | No | Path for the companion mapping report Markdown file |
| `--quiet` | `-q` | `bool` | `false` | No | Suppress console mapping report output (file still generated) |
| `--deterministic` | — | `bool` | `false` | No | Replace timestamps in output with a fixed sentinel value for idempotency verification in CI |

## Input Contract

### Directory Structure

The `--from-aspire` path must point to a directory with the following minimum structure:

```
<path>/
├── main.bicep              # Required: top-level orchestrator
├── main.parameters.json    # Optional: parameter values
├── <service>/*.bicep       # Required: at least one service module
└── <dependency>/*.bicep    # Optional: dependency modules
```

### Required File: `main.bicep`

Must contain:
- At least one `module` declaration referencing a service Bicep file
- Module declarations identify services by their `Microsoft.App/containerApps` resource type

### Service Bicep Files

Each service module (e.g., `apiservice/apiservice.bicep`) is expected to contain:
- A `resource` declaration of type `Microsoft.App/containerApps@*`
- `configuration.ingress` block with `targetPort`, `external`, `transport`
- `template.containers[]` array with `image`, `name`, `env[]`
- Optional: `configuration.secrets[]` for connection strings

### Dependency Bicep Files

Each dependency module (e.g., `cache/cache.bicep`) is expected to contain:
- A `resource` declaration of type `Microsoft.Cache/redis@*` OR `Microsoft.App/containerApps@*` with a Redis container image
- Connection-related properties (host, port, keys)

## Determinism (FR-012)

The command guarantees byte-for-byte identical output when run on identical input artifacts:

- All resources, parameters, and mapping entries are emitted in lexicographic order by name
- Map-typed fields (environment variables) are iterated in sorted key order
- File discovery uses lexicographic path ordering
- When `--deterministic` is set, the `Date:` comment in `app.bicep` and `Generated:` field in `mapping-report.md` use a fixed sentinel (`DETERMINISTIC`) instead of the current timestamp

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success — app.bicep and mapping-report.md generated |
| 1 | Error — invalid input, missing files, or conversion failure |

## Examples

```bash
# Basic usage — convert azd infra synth output in ./infra
rad bicep generate --from-aspire ./infra

# Specify output paths
rad bicep generate --from-aspire ./infra --output ./deploy/app.bicep --report ./deploy/mapping-report.md

# Override application name
rad bicep generate --from-aspire ./infra --app-name my-app

# Quiet mode (suppress console report)
rad bicep generate --from-aspire ./infra --quiet

# Full workflow example
azd infra synth                                        # Generate Aspire artifacts
rad bicep generate --from-aspire ./infra               # Convert to Radius
rad deploy app.bicep --parameters apiserviceImage=myregistry/api:v1  # Deploy
```
