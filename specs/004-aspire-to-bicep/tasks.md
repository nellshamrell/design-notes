## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies — can start immediately
- **Foundational (Phase 2)**: Depends on Phase 1 — BLOCKS all user stories
- **US1 (Phase 3)**: Depends on Phase 2 — core conversion pipeline (MVP)
- **US4 (Phase 4)**: Depends on Phase 3 — reporter integrates into existing pipeline
- **US2 (Phase 5)**: Depends on Phase 3 and Phase 4 — gap reporting uses reporter infrastructure
- **US3 (Phase 6)**: Depends on Phase 3 and Phase 4 — determinism applies to both app.bicep and mapping report
- **Polish (Phase 7)**: Depends on all user story phases being complete

### User Story Dependencies

- **User Story 1 (P1)**: Can start after Foundational (Phase 2) — **MVP deliverable**, no dependencies on other stories
- **User Story 4 (P2)**: Can start after US1 (Phase 3) — reporter integrates into mapper/runner from US1
- **User Story 2 (P2)**: Can start after US4 (Phase 4) — gap entries integrate into reporter from US4
- **User Story 3 (P3)**: Can start after US4 (Phase 4) — determinism applies to both outputs

### Within Each User Story

- Core components (parser, mapper, generator) before integration (Runner.Run)
- Implementation tasks before test tasks
- Golden files can be created in parallel with implementation
- Story complete and checkpoint verified before moving to next priority

### Parallel Opportunities

- **Phase 2**: T003, T004, T005, T006 can all run in parallel (different files, only depend on T002 models.go)
- **Phase 3**: T007, T008, T009 can run in parallel (parser, mapper, generator are separate files, depend only on models.go); T011, T012, T013, T014 can run in parallel (test files and golden files)
- **Phase 4**: T020 can run in parallel with T016–T019
- **Phase 5**: T022, T027, T028 can run in parallel
- **Phase 6**: T033 can run in parallel with T030–T032
- **Phase 7**: T035, T036 can run in parallel

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Complete Phase 1: Setup (T001)
2. Complete Phase 2: Foundational (T002–T006)
3. Complete Phase 3: User Story 1 (T007–T015)
4. **STOP and VALIDATE**: Run `rad bicep generate --from-aspire testdata/aspire-starter/` and verify app.bicep output matches golden file
5. Deploy/demo if ready — this delivers a working conversion for the happy-path aspire-starter topology

### Incremental Delivery

1. Setup + Foundational → Foundation ready
2. Add User Story 1 → Test independently → **MVP! Working conversion for aspire-starter topology**
3. Add User Story 4 → Test independently → Adds mapping report tracing every field to its source
4. Add User Story 2 → Test independently → Adds error handling, gap reporting, and placeholders
5. Add User Story 3 → Test independently → Adds determinism guarantees for CI/automation
6. Polish → Final quality pass, godoc, lint, and end-to-end validation

### Parallel Team Strategy

With multiple developers:

1. Team completes Setup + Foundational together
2. Once Foundational is done:
   - Developer A: User Story 1 (blocks all other stories)
3. Once US1 is done:
   - Developer A: User Story 4 (reporter)
   - Developer B: User Story 2 test fixtures (T022) in parallel
4. Once US4 is done:
   - Developer A: User Story 3 (determinism)
   - Developer B: User Story 2 (remaining tasks — gap detection, placeholders, error handling)
5. Polish: Both developers
